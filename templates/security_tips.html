Security tips, in plain English

Short explanations that build your security vocabulary — one bite at a time.

What is HTTPS?

HTTPS encrypts the connection between a visitor's browser and your website. Without it, anyone on the same network could read the data passing between them. Look for the padlock icon in the browser — that means HTTPS is on.

What is a security header?

Security headers are small settings a web server sends with every page. They tell the browser how to behave more safely — for example, not to guess file types or not to allow your site to be embedded inside another site. Missing them isn't an attack, but it leaves doors unlocked.

Why is a .env file dangerous?

A .env file holds configuration — often secret keys, API tokens, or database settings. It belongs on the server only. If it's reachable from the internet, those secrets leak to anyone who asks. This is one of the most common accidental exposures.

What is directory listing?

If directory listing is enabled, someone who visits your site's folder address can see all the files inside it, like a big open filing cabinet. It may reveal backup files, source code, or internal documents that were never meant to be public.

Why should you protect your API keys?

An API key is like a keycard to a building. If it's pasted into code, committed to a public repository, or exposed in a config file, anyone who finds it can use it — often for free with your bill. Treat keys as secrets and keep them out of code and page source.

Why do errors matter?

When something goes wrong, a website can print detailed error messages with database names, file paths, or stack traces. That's useful for fixing bugs but also hands attackers a map of your system. Friendly, vague errors are better.
